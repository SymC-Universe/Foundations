## Purpose

Consolidate the current computational Function Map and Limit Map into a single auditable relation matrix without turning the present starting layers into a universal ontology.

The active project notation remains:

- lowercase chi = licensed scalar stability coordinate;
- capital Chi = base modal/vector stability representation;
- Chi_arc = architecture-level/conglomerate representation reconstructed through Stability Arc machinery where scientifically licensed.

Inheritance is not another layer. It is a qualified relation among admitted representations across embedding, coupling, scale transition, perturbation, or lineage.

## Relations currently supported as qualification questions

### 1. chi <-> Chi

Ask whether a licensed scalar is an adequate compression of the admitted modal/state structure for the declared task.

Possible outcomes:
- SCALAR_SUFFICIENT_FOR_TASK
- SCALAR_INFORMATION_LOSS
- SCALAR_REFUSED
- INDETERMINATE

A scalar can be mathematically licensed yet scientifically insufficient for the task.

### 2. Chi -> Chi_arc

Ask whether modal/state structure plus the declared coupling/interface predicts a separately measured architecture-level response.

The Chi_arc target must not be defined from the same predictor used to explain it.

Possible outcomes:
- modal structure materially predicts direct architecture response;
- MODAL_ONLY_SUFFICIENT;
- SYSTEM_ONLY_STRUCTURE_WITHOUT_INHERITANCE;
- NATIVE_FRAMEWORK_EQUIVALENT;
- NO_ADDED_INHERITANCE_VALUE;
- FRAMEWORK_NOT_OPERATIONAL.

### 3. History/context -> admitted representation

History, memory, or context is not automatically appended to Chi_arc.

It is admitted only when:
1. native dynamics or projection theory supports the need for it;
2. the declared observations contain enough information to identify/use it for the task;
3. a stronger native closure/filtering explanation is not being relabeled as SI novelty.

The fresh estimator ensemble shows that mathematical history can remain true while operational history utility disappears under noisy observations.

### 4. chi <-> Chi_arc

This relation is not presumed. It asks whether a scalar coordinate tracks, compresses, or predicts anything nonredundant about the independently reconstructed architecture-level target.

A valid outcome is that chi is admitted locally but is irrelevant or information-losing for Chi_arc.

### 5. Stability Inheritance relation

A candidate inheritance relation is evaluated only after the source and target representations are independently admitted.

A schematic relation may be written:

\[
\mathcal I: \mathfrak S_P \rightarrow \mathfrak S_D
\]

only as bookkeeping for a qualified source-to-descendant relation, not as a new force, layer, or universal map.

Candidate dispositions include:
- preservation;
- transformation;
- compensation/reorganization;
- nonidentifiability;
- loss;
- native-framework equivalence;
- no added inheritance value.

## Current architectural lesson

The computational program does **not** support a fixed ladder in which every system must possess chi, then Chi, then Chi_arc, then history.

What it supports is a **representation-qualification architecture**:

1. start from native dynamics;
2. admit only representations licensed for the task and regime;
3. test whether compression loses information;
4. preserve invariant/subspace structure when labels fail;
5. construct Chi_arc only from independent system-level evidence where possible;
6. add history/context only when both mathematically required and operationally identifiable;
7. test inheritance only after source and target objects are independently qualified;
8. permit native equivalence, refusal, and no-added-value outcomes.

This is a synthesis of current P0-Q evidence and remains open to revision.

## External measured benchmark constraint

Silverbox, Fine Steering Mirror, Wiener-Hammerstein, and F-16 GVT now provide four independent measured-data qualification lanes. Taken together they support a broader but still qualified transport statement: reduced/local representations can remain useful while representation adequacy changes with task, operating regime, embedded interface state, and recursive/global demand. F-16 adds a spatially organized structural case in which amplitude conditioning across a localized nonlinear interface materially improves held-out system-response transport. They do **not** establish an inheritance relation.

Across all four measured lanes:
- better nonlinear prediction is not automatically Chi_arc;
- local model adequacy is task- and regime-specific;
- physical chi is either refused or remains only a model-local diagnostic;
- native nonlinear system-identification explanations remain sufficient;
- no independently characterized source-to-target embedding or lineage transition has yet been tested.

Therefore the measured-data program strengthens the representation-qualification architecture while sharpening the residual Stability Inheritance question to cases with independently defined source and target objects plus an explicit carrier/correspondence map.

## Claim ceiling

This matrix is a working architecture map. It is not:
- proof of a universal stability architecture;
- proof that the three starting layers are exhaustive;
- an empirical inheritance result;
- a replacement for domain-native models;
- a GOM notation amendment.


## F-16 GVT addition

The F-16 FullMSine P0-Q test adds a measured structural-dynamics relation not present in the previous three-benchmark synthesis. Using only estimation levels 1, 3, 5, and 7, complex FRFs were interpolated in the published force-RMS coordinate and evaluated on reserved levels 2, 4, and 6 in a preregistered 6.5-8.2 Hz band around the published wing-torsion mode.

The amplitude-conditioned representation beat the fixed Level-1 representation at all three reserved levels, with primary error ratios 0.533, 0.117, and 0.0335. The same direction held separately at the excitation, wing-side, and payload-side outputs. The interface-adjacent relative-response proxy also changed substantially with excitation level.

This is classified as **ARCHITECTURE_SUPPORTING_NATIVE**. It is positive evidence for the reconstruction because it establishes an organized relation between embedded interface regime and realized multi-location system response. It remains native-model compatible and does not itself establish Stability Inheritance added value.

This addition sharpens the architecture question from merely "which representation fits better?" to "which embedded constraints or local regimes condition the realized system representation, and when can those relations be transported prospectively?"


## pyFBS measured hierarchical-transformation addition

The current-metadata pyFBS SVT/LM-FBS lane supplies a distinct architectural relation from the nonlinear system-identification benchmarks and the F-16 operating-regime study.

The source objects were independently measured component B and assembled system AB. The native SVT basis/correspondence was frozen from B and AB while component A remained sealed. The resulting native LM-FBS decoupling was then compared with independently measured A.

Across all 800 positive-frequency bins:

- native recovered-A error = 1.20313;
- no-decoupling A-side baseline error = 1.25333;
- native decoupling improves the global error by 4.01%;
- native decoupling beats the baseline at 80.25% of bins.

This supports a measured hierarchical relation in which a component and its assembly contain enough structured information for an established native transformation to move an embedded response toward an independently measured component state.

The same result carries strong limits:

- absolute normalized recovery error remains greater than 1 globally;
- interface-matrix condition number has median 380.8, p90 3822, maximum 22322;
- the deterministic reduced-coordinate shuffle is only slightly worse globally and native wins against it in only 49.6% of bins.

Therefore the architectural inference is not "the carrier has been identified." It is:

**MEASURED_HIERARCHICAL_TRANSFORMATION_IS_OPERATIONAL_BUT_CONDITIONED**

with the separate novelty classification:

**NATIVE_FRAMEWORK_EQUIVALENT**.

## Combined F-16 + pyFBS architectural consequence

The two measured structural lanes now establish complementary pieces:

1. **F-16:** an embedded local interface/operating regime conditions the realized multi-location response organization, but the conditioning does not collapse to one universal scalar amplitude map.
2. **pyFBS:** independently measured component and assembly objects participate in an explicit native hierarchical transformation that partially recovers an independently measured component target, but the transformation is strongly conditioned and does not establish unique carrier specificity.

Together they strengthen a relational view of Stability Architecture. The evidence is better represented as

\[
\text{admitted local/component structure}
+
\text{coupling/interface/context}
\xrightarrow{\text{native transformation / organization}}
\text{realized system response}
\]

than as a universal ladder from scalar to modal to conglomerate coordinates.

This remains a working architecture relation, not a new law or force.


## BARC boundary-condition addition

Published BARC experiments add a native piece that is not reducible to nonlinear model selection or component-to-assembly algebra. The same removable component is deliberately studied under different embedding constraints: its next-level Box assembly, traditional rigid fixtures, flexible/impedance-matched fixtures, free-free and fixed-base configurations, and altered attachment geometry.

The source literature establishes that modal and response behavior changes with these boundary realizations and that fixture design can be treated as the problem of reproducing the target assembly environment rather than eliminating fixture dynamics altogether.

Evidence role:

**ARCHITECTURE_SUPPORTING_NATIVE_BOUNDARY_CONDITION**

This supports an evidence-compatible relation:

component structure
+ interface/attachment state
+ boundary impedance
+ excitation/test context
-> realized component dynamics.

The BARC result sharpens a program-wide distinction: intrinsic/local characterization and embedded realized behavior are not interchangeable. The embedding constraints are part of the architecture whenever the native dynamics show that they materially condition the task.

The current public Test Data share is inaccessible from the computational runner, so BARC remains at the published-experimental evidence tier for now. That source-access limitation is kept separate from scientific interpretation.
