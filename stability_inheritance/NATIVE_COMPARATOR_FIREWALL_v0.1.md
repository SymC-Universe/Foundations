# Stability Inheritance Native Comparator Firewall v0.1

**Status:** ACTIVE / P0-N  
**Date:** 2026-09-27  
**Purpose:** Prevent Stability Inheritance from relabeling established hierarchical stability, coarse-graining, resilience, or multiscale-causation machinery as a new mechanism.

## Governing comparison rule

The SI question is not whether lower-level structure can influence higher-level behavior. That is already established in multiple native frameworks. SI must identify a stability-relevant lower-level object, keep modal/vector Χ separate from conglomerate/system Χ_con, state the carrier or transformation path, and show a prespecified contribution beyond the strongest native framework that addresses the same task.

A comparator failure is scientifically informative. If a standard native framework fully accounts for the frozen task, the SI result is EQUIVALENT or NO_ADDED_INHERITANCE_VALUE rather than a rescued inheritance claim.

## Comparator classes

| Resilience / viability / basin-stability frameworks | resistance, recovery, attraction basins, viable/recovery regimes, non-exact return, transition risk | that stability can mean recovery to a viable regime rather than the exact baseline | does lower-level χ or Χ constrain the shape/accessibility/evolution of the higher-level recovery landscape beyond native resilience descriptors? |

## Minimum SI added-value test

For a declared higher-level target R, compare at minimum:

- native higher-level model: R = f(H,U)
- native closure/compositional model where applicable: R = f_native(H,U,history/unresolved terms)
- SI candidate: R = f(H,U,L)
- SI relational candidate when justified: R = f(H,U,L,HxL)

Here H is the independently characterized higher-level state or organization, U is the perturbation/forcing, and L is independently characterized lower-level χ, Χ, carrier, or another specifically frozen inheritance object.

The estimator is not standardized across domains. The comparison structure is.

## Mechanistic inheritance ceiling

Incremental prediction alone does not establish a carrier mechanism. A mechanistic SI claim additionally requires:

1. independently characterized lower-level source before target exposure;
2. explicit carrier or transformation correspondence;
3. frozen mapping rule;
4. prospective target prediction;
5. intervention/counterfactual on the proposed source or carrier;
6. specificity controls showing that generic, scrambled, same-spectrum, or alternative carriers do not perform equally well.

These requirements retain the existing substrate-inheritance evidence ladder while broadening the investigation beyond material substrates.

## Refusal outcomes

- **NATIVE_MODEL_SUFFICIENT:** strongest native model accounts for the task; no added SI value.
- **CLOSURE_SUFFICIENT:** memory/closure framework accounts for the apparent inherited-history effect.
- **MODAL_ONLY:** Χ correspondence survives without evidence that Χ_con inherits the relation.
- **SYSTEM_ONLY:** Χ_con structure is informative but cannot be traced to the proposed lower-level source.
- **NONIDENTIFIABLE:** several lower-level sources produce indistinguishable higher-level outcomes under the observed data.
- **TRANSFORMED_NOT_INHERITED:** organization changes under embedding, but no prospectively stable lineage relation survives.
- **INHERITANCE_CANDIDATE:** lower-level information adds prespecified value but carrier mechanism remains unproven.
- **CARRIER_RESOLVED_INHERITANCE:** full prospective carrier/intervention/specificity gates survive.

These are investigation labels, not universal ontological classes.

## Current consequence

The most important novelty boundary is now clear: SI is not a theory that hidden scales matter, that component stability composes, that systems remember perturbations, that interventions can be mapped between causal levels, or that stability can be preserved under model abstraction. Its candidate contribution is a refusal-capable method for determining which *stability-relevant representations* survive, transform, or acquire nonredundant meaning across hierarchical embedding, and whether that relationship adds measurable value beyond the native framework already used for the declared task.
