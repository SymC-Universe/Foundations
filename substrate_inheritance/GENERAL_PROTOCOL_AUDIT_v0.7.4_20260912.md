## Required v0.7.4 corrections

### 1. Scalar/modal/conglomeration cannot remain three mandatory instantiated views

Finding: SI-next v0.3 requires exactly scalar, modal, and conglomeration relationship entries and treats missing primary views as a contract failure.

Problem: GP v0.7.4 treats scalar, vector/modal, and conglomerate/system as starting representations, not an exhaustive ontology, and permits `NOT_APPLICABLE` rather than manufacturing a layer.

Correction: SI-next v0.4 must permit an explicitly `NOT_APPLICABLE` starting representation. All three reporting slots may remain present for auditability, but an inapplicable layer must not count as a missing measurement or force a false scalar construction.

### 2. Local dynamical identity and embedded realized behavior must become first-class records

Finding: the existing SI machinery contains parent, child, coupling, self-energy, and lineage objects, but does not require an explicit local-versus-embedded audit object.

Correction: SI-next v0.4 records, where applicable:
- local/intrinsic subsystem object;
- outward coupling/signal;
- transformation by connected system/environment;
- feedback/return;
- embedded or closed-loop object;
- local properties that survive, transform, disappear, or emerge.

A system claim cannot be supported by isolated-component properties alone.

### 3. Pre-Atlas coordinate independence must be explicit

Finding: the existing v0.2 contracts already prohibit chi/kinetic target leakage into correspondence mapping, but the broader Atlas firewall is implicit.

Correction: SI-next v0.4 explicitly prohibits Atlas labels, desired Atlas regions, favored chi values, or favorable cross-domain agreement from defining or tuning SI coordinates, mappings, reductions, or a system scalar.

No system scalar may be created by averaging lower-level chi values. Any `chi_system` requires a separate native derivation and validation.

### 4. Participation, observability, identifiability, estimation, regime placement, and uncertainty must stay separate

Finding: current SI distinguishes participation and carrier correspondence and propagates some uncertainty, but the v0.3 candidate does not make the full GP separation explicit.

Correction: SI-next v0.4 keeps separate, where applicable:
- object existence/admission;
- participation/contribution;
- observability;
- identifiability;
- coordinate estimation;
- regime/branch placement;
- uncertainty/tolerance;
- final admission/refusal.

Weak observability may not be called physical absence. Strong participation may not be called identifiability.

### 5. Hierarchical closure requires its own gate

Finding: current lineage flow and higher-order source attribution can describe multiple transitions, but they do not by themselves qualify an effective subsystem for reuse at a higher level.

Correction: add a hierarchical-closure record with a declared higher-level question, validity regime, preservation target(s), reference object, reduced object, and one of:
- `HIERARCHICAL_REDUCTION_SUPPORTED_IN_REGIME`;
- `PARTIAL_HIERARCHICAL_CLOSURE`;
- `HIERARCHICAL_REDUCTION_FAILED`;
- `UNRESOLVED`;
- `NOT_APPLICABLE` for an unactivated gate.

Passing this gate means only that the declared higher-level information is preserved in the tested regime, not microscopic completeness.

### 6. Recovery/resilience must remain separate from state classification

Finding: SI has intervention maps and perturbative transfer but no explicit candidate recovery/resilience record.

Correction: add a separate recovery/resilience channel for systems where native dynamics support it. Current state, stability characterization, perturbation response, recovery/reorganization, and resilience erosion are distinct. Asymptotic return and finite-time transient amplification are distinct outputs.

No universal resilience metric is introduced.

### 7. Cross-scale recurrence needs an explicit scope firewall

Correction: SI-next must distinguish:
1. recurring mathematical motif;
2. preserved architecture across grouping/scale;
3. common physical mechanism;
4. common numerical chi region.

Evidence for one does not silently promote the next.

### 8. Function Map and Limit Map are currently imbalanced

Finding: the SI validation suite is exceptionally strong on limits, refusal, degeneracy, non-normality, identifiability failure, scalar non-uniqueness, and convergence boundaries. It is weaker on ordinary functioning landscapes showing where inheritance-like correspondence is stable, how coupling reshapes it across a supported interior, and how recovery/organization behaves before a limit is reached.

Correction: the next P0-D investigation must map ordinary supported regions as deliberately as failure regions. This includes coupling sweeps, lineage persistence/splitting/reconvergence maps, source-interaction surfaces, embedding-depth convergence surfaces, and recovery/transient maps where licensed.

The Function Map remains descriptive/structural until a mechanistic claim earns promotion.

### 9. Experimental-opportunity and literature-collision pass is missing

Correction: before targeted prior-experiment searching on a substantial SI question, preserve an independent experimental game plan after baseline native-science orientation. Then search prior experiments/methods, classify what is already answered, isolate any residual question, and decide whether a physical experiment is still worth building.

A separate `SI_EXPERIMENTAL_OPPORTUNITY_v0.1.md` is added before the targeted literature collision begins.

### 10. Attribution and residual novelty accounting is missing

Correction: add an SI attribution/residual-novelty ledger. Established Green-function reduction, Schur complements, modal/subspace comparison, biorthogonal spectral geometry, system identification, perturbation response, and related native methods must receive their actual credit. Any SI contribution is only the residual combination, formalization, prediction, validation, or tool behavior left after the nearest legitimate prior art is accounted for.

No `NO_CLOSE_PRECEDENT_FOUND` state may be treated as proof of novelty.

### 11. P0-Q search history should be explicit

Correction: add a visible qualification-search ledger identifying candidate versions, failure modes targeted, complexity added, reused known-truth evidence, and stopping rationale before any P1 specification is proposed.
