### Required v0.7.4 remediations

1. **S/M/C applicability.** SI-next v0.3 treats scalar/modal/conglomeration as mandatory minimum views. v0.7.4 treats them as starting representations and permits `NOT_APPLICABLE`. v0.4 must use a claim-specific applicability manifest.
2. **Local versus embedded stability.** Add separate local dynamical identity and embedded realized behavior. A local parent scalar/mode may remain unchanged while coupling changes the realized child/global behavior.
3. **Pre-Atlas coordinate independence.** Explicitly prohibit constructing a system scalar by averaging or conglomerating lower-level chi values. Any system scalar requires a separate native derivation.
4. **Separate dispositions.** Keep participation, observability, identifiability, coordinate estimation, regime placement, resolution, and uncertainty independently auditable.
5. **Hierarchical closure.** Add a closure gate with `SUPPORTED`, `PARTIAL`, `FAILED`, `NOT_APPLICABLE`, and `UNRESOLVED` states. A grouped subsystem must preserve the quantities needed for the declared higher-scale question within a stated validity regime.
6. **Recovery/resilience.** Add optional recovery/resilience records, separating asymptotic return from finite-time transient amplification where licensed. Adding the field creates no recovery claim.
7. **Function/Limit balance.** Future P0-D records identify `FUNCTION_MAPPING`, `LIMIT_MAPPING`, or both. Milestone review must detect limit-only overfocus.
8. **Cross-scale recurrence.** Separate repeated mathematical motif, preserved architecture, common mechanism, and shared numerical chi. Numerical similarity alone is never inheritance or common mechanism.
9. **Experimental Opportunity and Literature Collision Pass.** Add baseline native science -> independent experimental game plan -> targeted prior-experiment search -> residual-question isolation -> experiment disposition.
10. **Attribution/novelty integrity.** Add nearest-prior-art and residual-novelty accounting. No novelty is earned by creating the ledger.
11. **Run economy / continuity.** Future substantial physical runs require cheap preflight, representative pilot, deterministic/transient failure classification, resumable state, and stale/supersession guards. Existing small synthetic validation need not receive unnecessary release machinery.
12. **System Model / Engine terminology.** The SI scientific representation is the System Model; `inheritance_engine.py` is an executable implementation, not the scientific model itself.
13. **Rare/extreme proportionality.** H/Ru(0001) and other contrast/limit cases remain useful Limit Map testbeds but do not dominate interpretation merely by rarity.
