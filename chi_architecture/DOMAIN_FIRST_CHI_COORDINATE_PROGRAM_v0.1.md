# Domain-First Chi Coordinate Program v0.1

**Date:** 11 September 2026  
**Status:** P0-D / P0-Q research architecture, not confirmation  
**Authority:** General Cross-Project Research Protocol v0.7.1 FINAL + v0.7.1A Functional Mapping and Natural Limit-Testbed Addendum  
**Purpose:** determine whether each domain admits a scientifically useful architecture-derived coordinate before any cross-domain Stability Architecture Atlas is constructed.

## 1. Core ordering

The program adopts the following dependency:

`native domain science -> functioning/limit architecture -> candidate Chi coordinate map -> within-domain qualification -> frozen domain map -> cross-domain Atlas`

The inverse dependency is forbidden:

`cross-domain Atlas pattern -> tune domain coordinate -> rediscover the same Atlas pattern`

The Atlas is therefore a downstream record of independently earned domain placements. It is not an optimizer for the coordinate definition.

## 2. Working mathematical object

For domain `d`, condition/state `x`, and native governing description `G_d`, let the measurable architecture be

`A_d(x) = {native scalar content, modal/vector carriers, coupling/system organization, feedback/relationships, uncertainty/nonidentifiability, and any additional domain-native structure that earns admission}`.

The candidate chi object is a coordinate-generating map

`Chi_d : A_d(x) -> Z_d`,

where `Z_d` is the smallest scientifically adequate coordinate space supported by that domain.

`Z_d` is not required to be one-dimensional.

Allowed forms include:

- scalar coordinate;
- vector coordinate;
- subspace/projector coordinate;
- graph/network coordinate;
- operator-valued or manifold coordinate;
- discrete regime/topology label plus continuous coordinates;
- `NO_ADMISSIBLE_CHI_COORDINATE` when no scientifically defensible compression or placement exists.

A lowercase scalar `chi_d` is admitted only when a one-dimensional compression earns its existence from native science and preserves the information required for the declared task.

## 3. Meaning of conglomeration

The coordinate may depend on several ingredients jointly, but `conglomerate` does not mean an arbitrary aggregate or a score formed by averaging whatever measurements are available.

A conglomerate contribution must arise from a named native relationship such as:

- physical coupling between subsystems;
- feedback or control paths;
- cross-layer mappings;
- network topology;
- interaction terms;
- memory kernels;
- substrate-mediated self-energy or effective dynamics;
- coupled covariance/operator structure;
- reaction-network structure;
- other domain-native joint organization.

The candidate coordinate must preserve contradictions and refusals. A strong component cannot numerically cancel a failed required component unless the native mathematics itself derives such cancellation.

## 4. Domain-first firewall

Before a domain contributes to the cross-domain Atlas, the following must be done without using the desired cross-domain alignment as a selection criterion:

1. specify the native governing object or accepted empirical representation;
2. identify measurable system components and couplings;
3. build a Function Map across ordinary supported behavior;
4. build a Limit Map across perturbations, transitions, model breakdowns, and qualified rare natural testbeds where available;
5. identify which quantities are actually observable and which are nonidentifiable;
6. define candidate coordinate map(s) using only within-domain scientific objectives;
7. compare against the strongest fair native description for the declared task;
8. determine whether the coordinate adds, preserves, compresses, or loses scientifically relevant information;
9. freeze the domain map before cross-domain placement is inspected for confirmatory purposes.

A domain may remain scientifically useful even if step 6 returns no compact chi coordinate.

## 5. What makes a coordinate earn its existence

A candidate coordinate is not admitted because it resembles a historical chi, clusters attractively, aligns across domains, or produces a visually coherent Atlas.

It must earn a role through one or more predeclared domain-native properties, such as:

- predicting an independently defined future response;
- locating a native transition or regime boundary;
- preserving a robustness or recovery property;
- remaining stable under admissible representation changes;
- improving out-of-sample description relative to a simpler compression;
- preserving coupling-sensitive behavior lost by isolated-component summaries;
- transporting across conditions or related systems under a frozen transformation;
- reducing dimension with quantified and acceptable information loss;
- exposing a mechanistic relation not recoverable from the compared reduced views.

A candidate that merely summarizes the same information more compactly may still be useful, but it must be labeled `COMPRESSION` rather than `ADDED_MECHANISM` or `ADDED_PREDICTION`.

## 6. Function Map before Atlas placement

For each domain, sample the functioning interior rather than only designed failures.

Where meaningful, characterize trajectories over native control parameters and perturbations:

- baseline/nominal function;
- ordinary variation;
- perturbation with successful recovery or redistribution;
- alternative stable organizations;
- transition/boundary region;
- post-transition/failure/refusal region;
- rare natural limit states.

The goal is a response surface or trajectory map, not a binary pass/fail table.

The coordinate candidate should be evaluated over the full supported response surface so that a boundary-only scalar is not mistaken for a complete architectural coordinate.

## 7. Rare natural occurrences as limit testbeds

Qualified rare natural occurrences are high-information probes of the Limit Map.

They may be used to test whether a domain coordinate:

- extrapolates toward a natural limit;
- changes topology or dimension;
- loses identifiability;
- reveals a saturation or compensation limit;
- refuses appropriately;
- distinguishes ordinary perturbation from exceptional reorganization.

Rare-event selection must be based on domain-native rarity or extremeness, not on observed chi placement or favorable agreement.

For P1 use, selection and inclusion rules must be frozen before the decisive chi/Atlas result is inspected. Already-viewed rare events remain valid P0-D/P0-Q calibration and mechanism evidence but cannot confirm rules learned from them.

Rare events are not treated as representative of ordinary prevalence unless the sampling design supports that inference.

## 8. Atlas construction only after domain maps exist

The eventual cross-domain Stability Architecture Atlas should contain, at minimum, for every admitted coordinate:

- domain and system identity;
- state/condition identity;
- governing/native-model identity;
- coordinate object and dimensionality;
- architecture ingredients used to construct it;
- observable/nonidentifiable components;
- Function-Map location;
- Limit-Map location;
- ordinary vs perturbational vs boundary vs rare-natural-testbed status;
- uncertainty;
- native comparator;
- coordinate admission status;
- evidence maturity;
- provenance and independence grade.

The Atlas must retain domain-native coordinates even when they cannot be placed on a single common numerical axis.

Cross-domain alignment is a second scientific problem, not an assumption.

## 9. Cross-domain alignment test

Only after at least two domain maps are independently qualified may candidate correspondences be examined.

Permissible questions include:

- do distinct `Chi_d` maps share the same ordering of functional -> perturbed -> boundary states?
- are there transformation-invariant relationships between coordinate components?
- does coupling or feedback change coordinate location in structurally similar ways?
- do independent domains exhibit analogous loss of compensatory freedom, modal reorganization, or system-level transition?
- is there a low-dimensional common embedding that preserves native domain outcomes better than chance or simpler descriptors?

Cross-domain similarity discovered at this stage is P0-D until a mapping rule is frozen and tested on untouched domain/system evidence.

No domain coordinate may be retroactively changed merely to improve cross-domain overlap. Any revised coordinate becomes a new version and inherits promotion debt from the viewed Atlas pattern.

## 10. Scalar rule

The program does not search for a scalar merely because historical chi was scalar.

If `Chi_d` can be faithfully represented by one dimension for the declared task, a scalar projection may be proposed:

`chi_d = P_d(Chi_d)`.

The projection must quantify what information is preserved and what is lost.

If modal, coupling, or conglomerate organization is essential to the task and cannot be compressed without unacceptable loss, the correct result is a multidimensional coordinate or `NO_ADMISSIBLE_SCALAR_CHI`.

## 11. Initial domain sequence

The first pass should prioritize domains with mature native mathematics or existing audited evidence, while keeping already-viewed evidence in P0-D/P0-Q status:

1. second-order damped dynamics as the exact scalar anchor;
2. coupled/non-normal linear dynamics as a case where spectrum alone is insufficient;
3. NSD synthetic known-truth dynamics for observable-rank, modal, system, and refusal behavior;
4. GRI static multi-omic architecture as a non-temporal biological architecture case with biological chi deliberately withheld;
5. substrate-inheritance coupled dynamics as a direct component/coupling/whole-system test;
6. Chemistry reaction/network cases where single-barrier and network-resolved representations can be contrasted;
7. additional mature domains such as power-grid, seismological, quantum/open-system, and cosmological cases only after each receives its own domain-native audit.

This ordering is developmental, not a ranking of evidentiary importance.

## 12. Anti-circularity checklist for every domain

Before any candidate coordinate result is interpreted, record:

- Was the target/outcome defined independently of the coordinate?
- Were coordinate ingredients chosen without viewing desired Atlas placement?
- Was the governing/native model chosen independently of the candidate chi result?
- Does any predictor share an algebraic denominator, baseline, or preprocessing target with the outcome?
- Does the coordinate contain the outcome directly or through a deterministic transformation?
- Were hyperparameters tuned on the same states used to claim performance?
- Is the comparator fair for the declared task?
- Are independent units and exchangeability valid?
- Can the method return `NO_ADMISSIBLE_CHI_COORDINATE`?
- Can a domain produce a valid Function Map without producing a compact chi?
- Can the cross-domain Atlas fail to align the independently qualified domain maps?

If any answer creates a dependence capable of forcing the claimed agreement, the result is exploratory/calibration only until independently tested.

## 13. Current claim ceiling

This document defines a research order and candidate mathematical role for chi. It does not establish that every domain admits a chi coordinate, that independently derived domain coordinates align, that architectural chi is universal, or that a cross-domain Stability Architecture Atlas exists as a validated scientific object.

The first scientifically meaningful milestone is therefore not an Atlas. It is a set of independently auditable **domain Chi maps**, including domains that return partial, multidimensional, or refused coordinate structures.
